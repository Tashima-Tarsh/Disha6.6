## 1. System Identity & Mission

**DISHA 6.6 (Defense & Intelligence Sovereign Hyper-Awareness)** is a sovereign, air-gapped, multi-agency intelligence operating system and investigative workbench. Engineered for defense analysts, law enforcement authorities, digital forensic examiners, and national security professionals, DISHA unifies heterogeneous open-source intelligence (OSINT), national registry records, cyber threat telemetry, and entity-relationship graphs into a mathematically corroborated, court-admissible evidence stream.

Unlike conventional OSINT utilities that function as disjointed scripts or cloud-dependent aggregators, DISHA operates on a **Truth-First, Zero-Trust Architecture**. It treats every ingested artifact—whether a vehicle registration record, electoral demographic marker, passive DNS query, or social identifier—as an unverified claim until it undergoes cryptographic sealing, cross-registry corroboration, and adversarial contradiction detection.

All analytical conclusions produced by DISHA 6.6 are bound to a tamper-evident digital ledger structured in strict accordance with the **Bharatiya Sakshya Adhiniyam (BSA), 2023 (Sections 61, 63, and 65B)** and the **Digital Personal Data Protection Act (DPDPA), 2023**, guaranteeing full legal admissibility in courts of law.

### 2.1 Evidence-First Doctrine
No operational datum is accepted into an investigation based solely on API return codes. In DISHA 6.6:
1. Every observation is sealed with SHA-256/SHA-512 hashes at ingestion.
2. The data source, network protocol, collector identity, and UTC timestamp are immutably recorded.
3. Every finding maintains a bidirectional pointer: forward to synthesized intelligence dossiers and backward to raw binary packets or payload snapshots.

### 2.2 Truthful Execution & Capability Transparency
DISHA enforces strict state truthfulness across all intelligence adapters. Upstream tools and external data providers are categorized into verified states:
- `LOCAL_SMOKE_PASS`: Binary or service confirmed functional in the local isolated environment.
- `UNCONFIGURED`: Binary, dependency, or upstream network interface unavailable.
- `CREDENTIAL_REQUIRED`: Upstream requires authoritative institutional credentials.
- `REFERENCE_ONLY`: Offline knowledge base, dictionary, or static dataset.
The system refuses to generate synthetic, hallucinated, or mock results when an upstream tool is unconfigured.

### 2.3 Strict Defensive Isolation
All defensive formations and operational procedures follow non-retaliatory security parameters. DISHA strictly disallows unauthorized scanning, credential harvesting, remote exploitation, or destructive actions against external targets, serving purely for sovereign territorial protection, internal forensics, and lawful intelligence analysis.

### 6.1 The Six-Stage Autonomous Loop

1. **Target Classification**: The `UniversalTargetClassifier` inspects the input query using strict deterministic heuristics and regex pattern matching, identifying whether the target is a vehicle registration, electoral ID, phone number, email, domain, IPv4/v6, social handle, CVE code, or cryptographic hash.
2. **Autonomous Plan Generation**: The system evaluates available tools against the identified target type and compiles a typed Direct Acyclic Graph (DAG) using Zod-validated schemas. The plan enforces jurisdiction restrictions, passive-only boundaries, and timeouts.
3. **Governed Adapter Execution**: The plan is dispatched over the `OsintAdapterBus`. Inline passive adapters execute under strict bounded concurrency (default concurrency: 3) to prevent socket exhaustion and API rate-limiting.
4. **Observation Normalization**: Heterogeneous raw outputs are transformed into canonical `NormalizedObservation` entities, capturing entity attributes, location coordinates, temporal timestamps, and source provenance.
5. **Corroboration & Contradiction Resolution**: The engine analyzes cross-adapter claims. Multiple agreeing observations increment an entity's confidence score; conflicting observations (e.g., differing names for the same registration) are flagged in the contradiction matrix.
6. **Sovereign Dossier Synthesis**: An air-gapped sovereign reasoning model consumes the normalized evidence graph, generating an executive narrative with direct source citations and confidence breakdowns.

## 7. Court Admissibility & Constitutional Chain of Custody

A primary design mandate of DISHA 6.6 is ensuring that all gathered intelligence can withstand judicial scrutiny in legal proceedings.

```
+----------------------------------------------------------------------------------------------------+
|                         BHARATIYA SAKSHYA ADHINIYAM (BSA), 2023 COMPLIANCE                         |
+----------------------------------------------------------------------------------------------------+
|  [RAW INGESTION]  -->  [CRYPTO HASHING]  -->  [MERKLE CHAINING]  -->  [BSA SECTION 65B CERTIFICATE] |
|  - Packet Capture      - SHA-256 Hash          - Previous Hash Bind    - Cryptographic Hash String |
|  - JSON Payload        - SHA-512 Hash          - RFC 3161 Timestamp    - Collector User Identity   |
|  - HTTP Headers        - Hardware Token        - Postgres Audit Ledger - System Device Signature   |
+----------------------------------------------------------------------------------------------------+
```

### 7.1 Statutory Grounding: Bharatiya Sakshya Adhiniyam, 2023
- **Section 61 (Admissibility of Electronic Records)**: Treats electronic records on par with physical documentary evidence when integrity is demonstrated.
- **Section 63 (Conditions for Admissibility of Electronic Records)**: Automates technical proof that the computing devices producing the intelligence were operating properly and that the data has not been modified during processing.
- **Section 65B Certificate Generation**: The system automatically compiles the mandatory statutory certificate for electronic evidence presented in court, including:
  - Exact cryptographic hash (SHA-256) of the raw stored artifact.
  - Identification of the system, hardware signature, and terminal used for collection.
  - Identity, badge number, and digital signature of the investigating officer.
  - Complete, unbroken audit trail from ingestion through presentation.

### 7.2 Immutability & Tamper-Evident Storage
The **Evidence Ledger** utilizes continuous cryptographic chaining. Each evidence block contains:
$$\text{Block Hash} = \text{SHA-256}(\text{Index} \parallel \text{Timestamp} \parallel \text{Collector ID} \parallel \text{Payload Hash} \parallel \text{Previous Block Hash})$$
Any retroactive modification of an artifact, timestamp, or investigator identity invalidates the chain forward from that block, immediately alerting audit supervisors.
