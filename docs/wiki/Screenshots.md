# Screenshot capture plan

The repository contains an active UI, but documentation should show real states instead of fabricated screenshots. Capture images from a controlled deployment containing only synthetic or expressly publishable records; redact names, credentials, tokens, private sources and incident evidence.

| Proposed image | Route | Show | Caption |
| --- | --- | --- | --- |
| `docs/images/dashboard.png` | `/dashboard` | Navigation, source readiness and evidence overview | Analyst command dashboard with sourced state |
| `docs/images/workbench.png` | `/workbench` | A safe sample mission and its policy/evidence result | Mission flow with reviewable evidence |
| `docs/images/intelligence.png` | `/intelligence` | Public-source search or watch state | Governed intelligence workspace |
| `docs/images/system.png` | `/system` | Runtime status without secrets | System health and dependency checks |

Use a consistent desktop viewport, record the commit and environment used, and link images from the README only after files exist. The current README uses the checked-in SVG social preview as a banner and Mermaid for exact relationships.
